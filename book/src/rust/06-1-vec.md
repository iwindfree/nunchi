# 6.1 `Vec<T>`와 슬라이스

> **선행 장**: [0.3 타입 표기 읽는 법](00-3-types.md), [1.3 빌림](01-3-borrow.md)
> **연습문제**: 3개

목록을 다루는 두 타입입니다. 관계가 `String`과 `&str`의 관계와 같습니다.

## `Vec<T>`는 소유합니다

크기가 실행 중에 정해지는 목록입니다.

```rust
let mut nodes: Vec<Node> = Vec::new();
nodes.push(node);
```

자주 쓰는 메서드입니다.

| 메서드 | 하는 일 |
|---|---|
| `.push(v)` | 뒤에 넣습니다 |
| `.pop()` | 뒤에서 꺼냅니다. 비면 `None`입니다 |
| `.len()`, `.is_empty()` | 개수를 봅니다 |
| `.first()`, `.last()` | 앞뒤 값을 빌립니다. 비면 `None`입니다 |
| `.get(i)` | `i`번째를 빌립니다. 없으면 `None`입니다 |
| `.contains(&v)` | 값이 있는지 봅니다 |
| `.sort_by(f)` | 정렬합니다 |
| `.retain(pred)` | 조건에 맞는 것만 남깁니다 |
| `.truncate(n)` | 앞에서 `n`개만 남깁니다 |
| `.extend(iter)` | 다른 목록을 이어 붙입니다 |
| `.dedup()` | 이웃한 중복을 지웁니다 |

`v[i]`로도 꺼낼 수 있지만 없는 자리를 읽으면 프로그램이 멈춥니다.
`.get(i)`는 `Option`을 돌려주므로 안전합니다.

## 슬라이스 `&[T]`는 빌립니다

목록의 일부나 전부를 빌린 것입니다.

```rust
let all: &[Node] = &nodes;          // 전체를 빌립니다
let some: &[Node] = &nodes[0..3];   // 앞 세 개만 빌립니다
```

**함수 매개변수에는 `&[T]`를 씁니다.**

```rust
// 좋습니다
pub fn upsert_nodes(&mut self, nodes: &[Node]) -> Result<usize>

// 이유 없이 제약을 겁니다
pub fn upsert_nodes(&mut self, nodes: &Vec<Node>) -> Result<usize>
```

`&[T]`가 더 넓게 받습니다. `Vec`도 되고 배열도 되고 다른 슬라이스도 됩니다.
`&Vec<T>`는 `Vec`만 받습니다.

`Vec`을 넘길 때 `&nodes`라고 쓰면 Rust가 자동으로 슬라이스로 바꿔 줍니다.

## 이 프로젝트에서는

### 매개변수는 슬라이스로 받습니다

```rust
// crates/nunchi-core/src/store/mod.rs 에서
fn upsert_nodes(&mut self, nodes: &[Node]) -> Result<usize>;
fn upsert_edges(&mut self, edges: &[Edge]) -> Result<usize>;
fn neighbors(&self, id: &NodeId, kinds: &[EdgeKind], dir: Direction, depth: u32)
    -> Result<Vec<Node>>;
```

받을 때는 `&[T]`, 돌려줄 때는 `Vec<T>`입니다. 함수 안에서 만든 목록은 빌려서
돌려줄 수 없기 때문입니다([1.6장](01-6-lifetimes.md)).

### 정렬하고 자릅니다

```rust
// crates/nunchi-core/src/pack.rs 에서
scored.sort_by(|a, b| b.1.total_cmp(&a.1));
scored.truncate(opts.candidate_limit);
```

점수 순으로 정렬한 다음 상위 120개만 남깁니다.

`sort_by`가 받는 클로저는 두 값을 비교해서 순서를 알려 줍니다. `b`와 `a`의
순서가 뒤바뀐 이유는 **큰 것부터** 놓기 위해서입니다. `a.1.total_cmp(&b.1)`로
쓰면 작은 것부터가 됩니다.

`total_cmp`는 실수를 비교합니다. 실수에는 `NaN`이 있어서 보통 비교로는
순서를 정할 수 없는 경우가 생기는데, `total_cmp`가 그것까지 처리합니다.

### 조건에 맞는 것만 남깁니다

```rust
// crates/nunchi-core/src/semantic.rs 에서
parts.retain(|p| p.len() > 1);
```

한 글자짜리 조각은 검색에 도움이 안 되므로 버립니다.

### 중복을 지웁니다

```rust
// crates/nunchi-core/src/semantic.rs 에서
tokens.sort();
tokens.dedup();
```

`dedup`은 **이웃한** 중복만 지웁니다. 그래서 먼저 정렬해야 전부 지워집니다.

## 크기가 정해진 배열

`Vec`과 달리 크기가 컴파일 시점에 정해집니다.

```rust
let weights: [f32; 5] = [0.7, 0.5, 0.3, 0.4, 0.2];
```

nunchi에서는 상수 목록에 씁니다.

```rust
// crates/nunchi-core/src/rules.rs 에서
["get", "post", "put", "delete", "patch"]
    .iter()
    .map(|s| s.to_string())
    .collect()
```

배열을 만들어 놓고 이터레이터로 `Vec`을 만듭니다. 배열은 힙을 쓰지 않으므로
이 방식이 `vec![]`보다 조금 낫습니다.

## 정리

`Vec<T>`는 목록을 소유하고 `&[T]`는 빌립니다. 함수 매개변수에는 `&[T]`를 써서
더 넓게 받고, 반환값에는 `Vec<T>`를 씁니다.

`v[i]`는 없는 자리를 읽으면 멈추므로 `.get(i)`를 쓰는 편이 안전합니다.

`dedup`은 이웃한 중복만 지우므로 먼저 정렬해야 합니다.
