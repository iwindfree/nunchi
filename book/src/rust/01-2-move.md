# 1.2 이동과 복사

> **선행 장**: [1.1 소유권이 무엇을 해결하는가](01-1-ownership.md)
> **연습문제**: 3개

앞 장에서 정수는 이동하지 않고 복사된다고 했습니다. 어떤 타입이 그런지, 그리고
왜 그런지 이 장에서 다룹니다.

## 스택과 힙

먼저 메모리가 두 곳으로 나뉜다는 사실을 알아야 합니다.

**스택**은 크기가 컴파일 시점에 정해진 값을 둡니다. 빠릅니다. 함수가 끝나면
그 함수의 스택 영역이 통째로 사라집니다.

**힙**은 크기가 실행 중에 정해지는 값을 둡니다. 빌리고 돌려주는 절차가
필요하므로 스택보다 느립니다.

```
스택                          힙
┌──────────────┐
│ count: 3     │              (아무것도 없습니다)
├──────────────┤
│ name         │             ┌─────────────┐
│  주소 ───────┼────────────▶│ "OrderSvc"  │
│  길이 8      │             └─────────────┘
│  용량 8      │
└──────────────┘
```

`count`는 정수이므로 스택에 값이 그대로 있습니다.

`name`이 `String`이라면 스택에는 **세 가지 정보**만 있습니다. 힙에 있는 실제
문자의 주소, 현재 길이, 확보한 용량입니다. 실제 문자는 힙에 있습니다.

## 이동이 실제로 하는 일

```rust
let a = String::from("OrderSvc");
let b = a;
```

여기서 힙에 있는 문자는 **복사되지 않습니다.** 스택에 있는 세 정보만 `b`로
옮겨집니다.

```
이동 전                        이동 후
┌──────────────┐              ┌──────────────┐
│ a: 주소,길이 │              │ a: (쓸 수 없음)│
└──────┬───────┘              ├──────────────┤
       │                      │ b: 주소,길이 │
       ▼                      └──────┬───────┘
┌─────────────┐                      │
│ "OrderSvc"  │◀─────────────────────┘
└─────────────┘               힙은 그대로입니다
```

**이동은 빠릅니다.** 힙 데이터를 건드리지 않고 스택의 작은 정보만 옮기기
때문입니다. 그래서 Rust에서 큰 데이터를 함수에 넘길 때 이동을 쓰는 것이
비효율적이지 않습니다.

`a`를 쓸 수 없게 만드는 이유가 여기서 분명해집니다. `a`와 `b`가 같은 힙 주소를
갖고 있으므로, 둘 다 살아 있으면 함수가 끝날 때 같은 메모리를 두 번 돌려주게
됩니다.

## `Copy` 타입

크기가 정해져 있고 힙을 쓰지 않는 타입은 복사해도 비용이 거의 없습니다.
이런 타입은 이동 대신 복사됩니다.

| `Copy`인 타입 | `Copy`가 아닌 타입 |
|---|---|
| `i32`, `u64`, `usize` 등 모든 정수 | `String` |
| `f32`, `f64` | `Vec<T>` |
| `bool`, `char` | `HashMap<K, V>` |
| `&T` (빌린 참조) | 구조체 (직접 표시하지 않으면) |
| 모든 필드가 `Copy`인 튜플과 구조체 | 열거형 (직접 표시하지 않으면) |

`String`이 `Copy`가 아닌 이유가 위 그림에서 설명됩니다. 힙 데이터를 복사하려면
실제로 문자를 다 복사해야 하고, 그것은 무료가 아니기 때문입니다. Rust는
비용이 드는 일을 몰래 하지 않습니다.

## 구조체를 `Copy`로 만들기

모든 필드가 `Copy`라면 구조체도 `Copy`로 만들 수 있습니다.

```rust
// crates/nunchi-core/src/model.rs 에서
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub struct Span {
    pub start_line: u32,
    pub end_line: u32,
}
```

`Span`은 `u32` 두 개뿐이므로 8바이트입니다. `Copy`로 만들어 두면 코드가 훨씬
편해집니다.

```rust
let span = node.span;          // 복사됩니다
process(span);
println!("{:?}", span);        // 여전히 쓸 수 있습니다
```

`Copy`가 아니었다면 매번 `&`를 붙이거나 `.clone()`을 불러야 했을 것입니다.

반면 `Node`는 `Copy`가 아닙니다.

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Node {
    pub id: NodeId,            // 안에 String 이 있습니다
    pub name: String,
    // ...
}
```

`String`이 들어 있으므로 `Copy`로 만들 수 없습니다. `Clone`만 붙어 있습니다.
`Clone`은 "복사할 수 있다"는 뜻이고, `Copy`는 "복사가 저렴해서 자동으로 해도
된다"는 뜻입니다. 그 차이를 다음 장에서 다룹니다.

## 함수에 넘길 때도 같습니다

```rust
fn consume(s: String) { }      // 소유권을 받습니다
fn look(s: &String) { }        // 빌립니다
fn take_num(n: u32) { }        // 복사됩니다

let text = String::from("hi");
consume(text);
println!("{}", text);          // 오류입니다. 이미 넘겼습니다

let count = 3;
take_num(count);
println!("{}", count);         // 정상입니다. 복사되었습니다
```

**함수 서명만 보면 소유권이 어떻게 되는지 알 수 있습니다.** `String`을 받으면
가져가고, `&String`을 받으면 빌리기만 합니다. 이것이 0.3장에서 함수 서명이
중요하다고 한 이유입니다.

## 연습문제

### 문제 1 [읽기]

아래 타입 중 `Copy`가 될 수 있는 것은 무엇입니까?

```rust
struct A { x: u32, y: u32 }
struct B { name: String }
struct C { span: Span, kind: u8 }     // Span 은 Copy 입니다
struct D { items: Vec<u32> }
```

<details>
<summary>정답 보기</summary>

`A`와 `C`입니다.

`A`는 `u32` 두 개이므로 됩니다. `C`는 `Copy`인 `Span`과 `u8`이므로 됩니다.

`B`는 `String`을 갖고 있고 `D`는 `Vec`을 갖고 있습니다. 둘 다 힙을 쓰므로
`Copy`가 될 수 없습니다.

규칙은 "모든 필드가 `Copy`여야 한다"입니다. 하나라도 아니면 전체가
`Copy`가 될 수 없습니다.

</details>

### 문제 3 [읽기]

`String`을 함수에 넘기면 힙에 있는 문자가 복사됩니까?

<details>
<summary>정답 보기</summary>

복사되지 않습니다.

스택에 있는 세 정보(주소, 길이, 용량)만 옮겨집니다. 힙 데이터는 그대로
있고 주인만 바뀝니다. 그래서 큰 문자열을 함수에 넘겨도 비용이 거의 없습니다.

복사가 일어나는 것은 `.clone()`을 부를 때입니다. 그때는 힙에 새 공간을 잡고
문자를 실제로 복사합니다.

</details>

## 정리

이동은 스택에 있는 작은 정보만 옮기므로 빠릅니다. 힙 데이터는 그대로 있고
주인만 바뀝니다.

크기가 정해져 있고 힙을 쓰지 않는 타입은 `Copy`이며 이동 대신 복사됩니다.
`Copy`로 만들려면 모든 필드가 `Copy`여야 합니다.

함수 서명을 보면 소유권이 어떻게 되는지 알 수 있습니다.
