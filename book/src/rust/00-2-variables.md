# 0.2 변수와 `let`, 그리고 기본이 불변인 이유

> **선행 장**: [0.1 Rust를 왜 이렇게 만들었는가](00-1-why-rust.md)
> **연습문제**: 2개

## 설명

Rust에서 변수는 `let`으로 만듭니다.

```rust
let count = 3;
```

여기서 다른 언어와 다른 점이 하나 있습니다. **이 변수는 값을 바꿀 수 없습니다.**

```rust
let count = 3;
count = 4;        // 컴파일 오류가 납니다
```

바꿀 수 있게 하려면 `mut`을 붙여야 합니다. `mutable`의 줄임말입니다.

```rust
let mut count = 3;
count = 4;        // 이제 됩니다
```

### 왜 불변이 기본인가

읽는 사람에게 정보를 주기 때문입니다. `let`으로 선언된 변수를 보면 그 값이
아래에서 절대 바뀌지 않는다고 확신할 수 있습니다. 함수가 100줄이어도 위쪽만
보면 됩니다.

그리고 0.1장에서 말한 소유권 추적과도 연결됩니다. 값이 바뀌지 않으면 컴파일러가
추적할 것이 줄어듭니다.

### 변수 가리기

Rust에서는 같은 이름으로 변수를 다시 선언할 수 있습니다. 이것을 변수
가리기(shadowing)라고 부릅니다.

```rust
let path = "src/main.rs";        // 문자열입니다
let path = normalize(path);      // 같은 이름으로 다시 선언합니다
```

두 번째 `path`는 첫 번째와 **다른 변수**입니다. 이름만 같습니다. 첫 번째
변수는 이제 접근할 수 없습니다.

이것이 재대입과 어떻게 다른지가 중요합니다.

```rust
let mut x = 3;
x = 4;                  // 재대입입니다. 같은 변수의 값을 바꿉니다

let y = 3;
let y = "세 개";        // 변수 가리기입니다. 새 변수를 만듭니다
```

재대입은 타입을 바꿀 수 없지만 변수 가리기는 바꿀 수 있습니다. 위 예에서 `y`는
정수에서 문자열로 바뀌었습니다.

## 이 프로젝트에서는

nunchi 코드에서 변수 가리기가 자주 나옵니다. 값을 단계적으로 변환할 때
중간 이름을 새로 짓지 않아도 되기 때문입니다.

```rust
// crates/nunchi-core/src/pack.rs 에서
let mut path = if out.starts_with('/') { out } else { format!("/{out}") };
while path.len() > 1 && path.ends_with('/') {
    path.pop();
}
```

여기서는 `mut`을 붙였습니다. `while` 반복에서 `path.pop()`으로 값을 계속 바꾸기
때문입니다.

반면 아래는 `mut` 없이 씁니다.

```rust
// crates/nunchi-core/src/framework.rs 에서
let trimmed = raw.trim().trim_matches(['"', '\'', '`']);
```

`trimmed`는 한 번 정해지면 바뀌지 않습니다. 그래서 `mut`이 없습니다. 읽는
사람은 이 값이 아래에서 그대로라고 믿을 수 있습니다.

**규칙은 간단합니다.** 기본은 `mut` 없이 쓰고, 컴파일러가 `mut`이 필요하다고
알려 줄 때만 붙입니다. 컴파일러가 정확히 알려 주므로 미리 고민할 필요가
없습니다.

```rust
let total = 10;
let total = total * 2;
let total = total + 5;
```

새 변수를 만들었기 때문입니다.

## 정리

변수는 `let`으로 만들며 기본적으로 바꿀 수 없습니다. 바꾸려면 `mut`을
붙입니다. 같은 이름으로 다시 선언하면 새 변수가 만들어지며, 이때는 타입을
바꿀 수 있습니다.
