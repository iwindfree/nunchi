# 8.4 다루지 않은 것들

> **선행 장**: [8.3 `Arc`와 `async`](08-3-async.md)
> **연습문제**: 없습니다.

이 책은 nunchi 코드에 실제로 나오는 문법만 다뤘습니다. Rust에는 여기서
설명하지 않은 기능이 더 있습니다.

이 장은 그중에서 **다른 Rust 코드를 읽을 때 만나게 될 것들**을 짧게
소개합니다. 자세히 설명하지는 않습니다. 언제 찾아보면 되는지 알려 드리는 것이
목적입니다.

## 이 코드에 없어서 다루지 않은 것

### `Box<T>`와 `dyn Trait`

nunchi에는 하나도 없습니다.

`Box<T>`는 값을 힙에 두는 상자입니다. 크기를 컴파일 시점에 알 수 없는 값이나
재귀적인 자료 구조에 씁니다.

`dyn Trait`은 **실행 시점에** 어떤 구현을 부를지 정하는 방식입니다. 다른
언어의 인터페이스 변수와 비슷합니다.

```rust
let stores: Vec<Box<dyn Store>> = vec![
    Box::new(SqliteStore::open(path)?),
    Box::new(MemStore::default()),
];
```

nunchi는 저장소 구현이 하나뿐이므로 이것이 필요 없었습니다. 대신 5.2장에서
본 방식을 씁니다.

```rust
pub fn describe<S: Store>(store: &S) -> String
```

이쪽은 컴파일 시점에 어떤 타입인지 정해지므로 실행 비용이 없습니다.
**구현이 여러 개이고 실행 중에 골라야 할 때만** `dyn`이 필요해집니다.
저장 계층을 실제로 교체하게 되면 그때 만나게 될 것입니다.

### `RefCell`과 `Mutex`

nunchi에는 없습니다.

1.3장의 빌림 규칙은 컴파일 시점에 검사합니다. 그런데 구조상 컴파일 시점에
증명할 수 없지만 실행 중에는 안전한 경우가 있습니다. 그때 검사를 실행
시점으로 미루는 장치가 `RefCell`입니다. 규칙을 어기면 컴파일 오류 대신
프로그램이 멈춥니다.

`Mutex`는 여러 스레드가 같은 데이터를 바꿔야 할 때 씁니다.

nunchi가 이것들을 피할 수 있었던 이유가 있습니다. **쓰기를 한 곳으로 모았기
때문입니다.** 인덱서만 데이터베이스에 쓰고 MCP 서버와 TUI는 읽기만 합니다.
공유해서 바꿔야 하는 상태가 없으므로 이 장치들이 필요 없습니다.

### 제네릭 함수를 직접 정의하는 일

nunchi에는 제네릭 함수가 없습니다. 0.3장에서 제네릭을 **읽는 법**만 다루고
**정의하는 법**은 다루지 않은 이유가 이것입니다.

`Vec<T>`나 `Option<T>`를 쓰기만 하고 직접 만들지는 않았습니다. 라이브러리를
만들게 되면 필요해집니다.

### `Iterator` 직접 구현

4.2장에서 이터레이터를 **쓰는 법**을 다뤘습니다. 직접 만드는 방법은 다루지
않았습니다. `Iterator` 트레이트의 `next` 메서드 하나만 구현하면 `map`,
`filter`, `collect`가 전부 따라옵니다.

nunchi는 표준 컬렉션이 주는 이터레이터만 쓰므로 직접 만들 일이 없었습니다.

### 연산자 오버로딩

`Add`나 `Index` 같은 트레이트를 구현하면 `+`나 `[]`를 자기 타입에 쓸 수
있습니다. nunchi에는 없습니다.

## 알아 두면 좋은 것

### `unsafe`

Rust의 안전 검사를 잠시 끄는 장치입니다. C 라이브러리를 부르거나 아주 낮은
수준의 최적화를 할 때 씁니다.

**nunchi에는 `unsafe`가 한 글자도 없습니다.** 대부분의 응용 프로그램이
그렇습니다. `unsafe`를 쓰지 않고도 필요한 것을 거의 다 할 수 있습니다.

### 매크로의 다른 종류

8.1장에서 다룬 `macro_rules!`는 선언적 매크로입니다. 이것 말고 절차적
매크로(procedural macro)가 있습니다. `#[derive(Serialize)]`가 그것입니다.

절차적 매크로는 별도 크레이트로 만들어야 하고 코드를 직접 조립합니다.
훨씬 강력하지만 만들기 어렵습니다. **쓰기만 하고 만들 일은 드뭅니다.**

### 비동기의 나머지

8.3장에서 `async`와 `await`를 필요한 만큼만 다뤘습니다. 실제로는
`Future`, `Pin`, 실행기(executor) 같은 개념이 더 있습니다.

`tokio`를 쓰는 응용 프로그램을 만드는 데는 8.3장 수준이면 충분합니다.
비동기 라이브러리를 직접 만들게 되면 더 알아야 합니다.

## 정리

이 책은 nunchi 코드를 읽는 데 필요한 문법만 다뤘습니다. `Box<dyn Trait>`,
`RefCell`, `Mutex`, 제네릭 정의, 연산자 오버로딩은 이 코드에 없어서
다루지 않았습니다.

없다는 사실 자체가 정보입니다. 이 코드베이스가 Rust 초보자에게 유리한 이유가
거기에 있습니다. 나중에 저장 계층을 교체하거나 라이브러리를 만들게 되면 그때
찾아보시면 됩니다.
