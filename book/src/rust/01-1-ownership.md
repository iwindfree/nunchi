# 1.1 소유권이 무엇을 해결하는가

> **선행 장**: [0.2 변수와 `let`](00-2-variables.md), [0.4 구조체, 열거형, 튜플](00-4-data.md)
> **연습문제**: 3개

이 장부터 여섯 장이 이 책에서 가장 중요한 부분입니다. Rust를 배우다 그만두는
사람들이 대부분 여기서 막힙니다. 천천히 읽으시기를 권합니다.

## 문제부터 봅니다

다른 언어에서 아래 코드가 어떻게 동작할지 생각해 보십시오.

```rust
let a = vec![1, 2, 3];
let b = a;
println!("{:?}", a);      // a 를 다시 씁니다
```

`vec![1, 2, 3]`은 정수 세 개를 담은 목록입니다. `Vec`은 크기가 정해지지 않은
데이터이므로 힙에 저장됩니다.

**Java나 Python이라면** `a`와 `b`가 같은 목록을 가리키고, 둘 다 정상으로
동작합니다. 가비지 컬렉터가 아무도 가리키지 않을 때 회수합니다.

**C++라면** 복사가 일어나거나(비용이 듭니다), 아니면 둘이 같은 메모리를 가리켜서
나중에 두 번 해제하는 오류가 날 수 있습니다.

**Rust는 컴파일을 거부합니다.**

```
error[E0382]: borrow of moved value: `a`
 --> src/main.rs:3:22
  |
2 |     let b = a;
  |             - value moved here
3 |     println!("{:?}", a);
  |                      ^ value borrowed here after move
```

## 왜 거부하는가

0.1장에서 말한 원칙을 다시 봅니다.

> 모든 값에는 소유자가 하나 있습니다. 소유자가 사라지면 값도 사라집니다.

`let b = a;`에서 목록의 소유자가 `a`에서 `b`로 **넘어갔습니다.** 이것을
**이동(move)** 이라고 부릅니다. 이제 `a`는 더 이상 소유자가 아니므로 쓸 수
없습니다.

소유자가 하나여야 하는 이유가 있습니다. 컴파일러는 소유자가 사라지는 시점에
메모리를 돌려주는 코드를 넣습니다. 소유자가 둘이면 두 번 돌려주게 되고, 그것이
바로 C++에서 오류가 나던 지점입니다.

```rust
{
    let a = vec![1, 2, 3];
    // ... a 를 씁니다
}   // 여기서 a 가 사라집니다. 컴파일러가 메모리를 돌려주는 코드를 넣습니다
```

소유자가 하나라는 규칙 덕분에 **가비지 컬렉터 없이도 언제 돌려줄지 정확히 알
수 있습니다.** 실행 중에 아무 검사도 하지 않으므로 비용도 없습니다.

## 어떻게 고치는가

세 가지 방법이 있습니다. 각각 다음 장들에서 다룹니다.

**첫째, 빌려 씁니다.** 소유자를 바꾸지 않고 잠깐 보기만 합니다.

```rust
let a = vec![1, 2, 3];
let b = &a;               // 빌립니다
println!("{:?}", a);      // a 는 여전히 소유자이므로 됩니다
```

[1.3장 빌림](01-3-borrow.md)에서 다룹니다. **대부분의 경우 이 방법이
정답입니다.**

**둘째, 복사합니다.** 값을 하나 더 만듭니다.

```rust
let a = vec![1, 2, 3];
let b = a.clone();        // 새 목록을 만듭니다
println!("{:?}", a);      // 됩니다
```

[1.4장](01-4-clone.md)에서 다룹니다. 비용이 들지만 때로는 정당합니다.

**셋째, 애초에 이동해도 되게 설계합니다.** `a`를 나중에 안 쓰면 이동이
문제가 아닙니다.

## 이동이 일어나지 않는 경우

모든 대입이 이동은 아닙니다.

```rust
let a = 3;
let b = a;
println!("{}", a);        // 정상으로 동작합니다
```

정수는 이동하지 않고 복사됩니다. 크기가 정해져 있고 스택에 있으므로 복사
비용이 거의 없기 때문입니다. 이런 타입에는 `Copy`라는 표시가 붙어 있습니다.
[1.2장](01-2-move.md)에서 어떤 타입이 여기에 해당하는지 다룹니다.

## 이 프로젝트에서는

nunchi 코드에서 이동을 실제로 활용하는 곳을 보겠습니다.

```rust
// crates/nunchi-core/src/index.rs 에서
stats.nodes = store.upsert_nodes(&nodes)?;
stats.edges = store.upsert_edges(&edges)?;
```

`&nodes`와 `&edges`에 `&`가 붙어 있습니다. 노드 목록을 **빌려서** 넘깁니다.
그래야 저장한 다음에도 `nodes`를 계속 쓸 수 있습니다.

반대로 이동을 쓰는 곳도 있습니다.

```rust
// crates/nunchi-core/src/framework.rs 에서
if !current.is_empty() {
    parts.push(std::mem::take(&mut current));
}
```

`std::mem::take`는 `current`의 내용을 꺼내 가고 그 자리에 빈 값을 남깁니다.
문자열을 복사하지 않고 소유권만 넘기므로 비용이 들지 않습니다. 이 코드는
식별자를 분해하면서 조각을 하나씩 목록에 넣는데, 조각마다 복사하면 낭비가
됩니다.

## 연습문제

### 문제 1 [읽기]

아래 코드 중 컴파일되는 것은 무엇입니까?

```rust
// (가)
let a = String::from("hello");
let b = a;
println!("{}", b);

// (나)
let a = String::from("hello");
let b = a;
println!("{}", a);

// (다)
let a = 42;
let b = a;
println!("{}", a);
```

<details>
<summary>정답 보기</summary>

(가)와 (다)가 컴파일됩니다.

(가)에서는 소유권이 `b`로 넘어갔고 `b`를 쓰므로 문제가 없습니다. 이동한 다음
새 소유자를 쓰는 것은 정상입니다.

(나)에서는 소유권이 넘어간 뒤에 이전 소유자 `a`를 쓰려고 하므로 오류가 납니다.

(다)에서는 `42`가 정수이므로 이동이 아니라 복사가 일어납니다. `a`와 `b`가
각각 자기 값을 갖습니다.

</details>

## 정리

값에는 소유자가 하나뿐입니다. 대입이나 함수 호출로 소유자가 바뀌면 이것을 이동이라
부르고, 이전 소유자는 더 쓸 수 없습니다. 소유자가 하나라는 규칙 덕분에 컴파일러가
메모리를 언제 돌려줄지 정확히 알 수 있으며, 실행 중 비용이 없습니다.

정수처럼 크기가 정해진 작은 값은 이동하지 않고 복사됩니다.
